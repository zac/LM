# Clock source and ownership audit

Read-only audit of AGC/LMCore at `b3f15533db335ee882dc07401790c93010809e8f`; LM integration checkout was `f9d77ea3a0b1c83dfafedd4768e579a5c24e8e08` when inspected. LMKit owns no clock behavior. This asset's neutral state is blank. Numeric review examples are fixtures, not an asserted launch epoch.

`AGC/Sources/LMCore/LMSimulation.swift` exposes `LMSimulationSnapshot.timeSeconds`, produced from private `elapsedTimeSeconds`. It starts at zero on reset, includes boot cycles converted to seconds, advances by simulation delta, and is restored from checkpoint `simulationTimeSeconds`. `LMFlightRecording.swift` records/interpolates that same elapsed timeline. It is not established launch GET. Pauses freeze the supplied snapshot time; accelerated simulation advances it faster than real time.

`AGC/Sources/AGC/AGC.swift` `AGCSnapshot` and `AGCRegisterSnapshot` do not include TIME1/TIME2. The runtime does expose `readDoublePrecision(ecadr:)`; `LMAGCNavState.swift` identifies TIME2=`0o24`, TIME1=`0o25`. A live atomic sample can be read from `runtime.readDoublePrecision(ecadr: Luminary099Erasable.time2)` and interpreted using `.decoded(scale: 28) / 100` seconds. Existing navigation code uses that pair in centiseconds. Those clock words are not recorded in the current replay frame. This API availability does not prove that current initialization establishes a particular historic GET.

`LMAGCPadLoad.swift` has TLAND/PDI constants and a `clockWords()` helper. No verified fixed mapping from simulation elapsed to launch GET was found. Do not add a PDI constant to `snapshot.timeSeconds`, display wall-clock time, or write AGC clock words simply to make the graphic look historically plausible.

Mission timer integration choices: keep the readout blank until a qualified GET sample exists; or explicitly label an app presentation as simulation elapsed and supply that value. Preserve the distinction in the user-facing app. The authored tuning-fork glyph historically reports fallback to the timer's internal oscillator after loss of external timing, and is not a generic missing-data indicator. It must stay dark unless that specific mode is implemented. Mission control bank is authored but uninstalled; there is no basis to bind those switches to AGC writes.

There was no existing mission/event timer state or API in LMCore or `PoweredDescentSession`. Event timer behavior is new app-owned instrument state driven by simulation timestamps. The separate coordinator worker supplies `LMEventTimerState`; its handoff defines reset/discontinuity/replay policy. Input handling should send START/STOP/RESET, select UP/DOWN, and held MIN/SEC slew press/release into that state, with a supplied simulation timestamp. A switch's physical detent and effective count direction are different: later hardware can change automatically to up-count after zero while the app retains its selected DOWN command separately from the lever pose. No AGC channel is inferred from this model's entity names.

All unsupported, nonfinite, missing, or replay-unqualified values must leave the readout blank rather than inventing zero. App stop/reset/discontinuity policies are reconstruction behavior, not claims about flight electronics, power, redundant timing, circuit breakers, or analog electrical faults.
