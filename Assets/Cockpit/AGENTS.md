# Cockpit asset work

Read `CONTRACT.md`, `../../Docs/CockpitCoordination.md`, and your component assignment before editing. Use a separate branch/worktree or clone for each component task.

Work only in the assigned component directory unless the current user explicitly expands the assignment. You may read shared research and existing assets. Do not edit another worker's files, the master assembly, the Xcode project, AGC/LMCore or LunarMap as part of a modeling assignment.

The integration owner maintains the master assembly and shared contracts. Propose contract changes in the component handoff. Source geometry, materials, mechanisms and naming must retain provenance and explicit uncertainty.

Use the existing AGC and LMCore through native application bindings. A component may be visual-only or a mechanical prototype until those bindings are tested. Do not create a substitute computer or flight simulation to make a preview appear connected.

Do not launch a heavy render or bake until the machine's render slot is assigned. There is no automatic render scheduler yet. Small review images belong in `review/`; disposable renders belong in ignored `renders/`.

Deliver a completed `HANDOFF.md` using `../../Docs/CockpitComponentHandoff.md` as the repository-root-relative template reference from `Assets/Cockpit`. Include exact source/dependency commits, Blender version, file paths, source evidence, export hash, performed checks and unresolved work.
