# Commander landing instruments runtime

This phase adds source-informed altitude/rate tapes, a later fly-to cross-pointer aid, physical AUTO/ATT HOLD and DES RATE controls, and optional cabin/breaker detail to the enclosed foundation. LMKit's accepted resource snapshot is `1285040`; AGC/LMCore remains `b3f15533db335ee882dc07401790c93010809e8f` with no behavior changes.

## Data and behavior

Altitude uses reconstructed geometric height, not the session's radar slant range. Rate is radial upward-positive in feet/second. Values outside the documented tape intervals or nonfinite values hide the corresponding rows and bring forward the authored unavailable shutter. Each row is placed from the contract's piecewise scale and enabled only while its full glyph fits the aperture; USD-authored hidden visibility is not used.

Cross-pointer input is reconstructed horizontal velocity in the yaw-defined lunar-surface frame. It is limited to landing programs 63–67 and valid flight states/headings. Fixed LO MULT full scale is ±20 ft/s, with saturated travel. Later fly-to convention moves the vertical bar left for rightward velocity and the horizontal bar up for forward velocity. This sign formula is an operational inference from [Luminary Memo 171](https://www.ibiblio.org/apollo/Documents/LUM171-DE_text.pdf), using [Memo 165](https://www.ibiblio.org/apollo/Documents/LUM165_text.pdf)'s later descent frame. It is not Apollo 11/Luminary 099 display output or a simulated landing-radar/AGS channel. Missing data hides both needles. Source qualifications remain in metadata and the optional training ornament; no simulation placard is added to the historical face.

AUTO/ATT HOLD uses the existing session API; OFF remains unsupported and rejected without moving the actuator. Selecting ATT HOLD does not itself guarantee P66. DES RATE preserves the existing held channel-16 input behavior: plus slows descent, minus speeds it. No app repeat timer or new engine logic is introduced. The existing simulation may process a held input each frame; this does not establish historically calibrated repeat timing. Release, cancellation, pause, stop, scene loss and cockpit exit neutralize DES RATE. Generation tokens prevent late drag samples from reacquiring after a forced release. The maintained attitude switch retains its state.

Dial markings and the attitude-mode face backing receive a bounded unlit material treatment preserving authored colors/textures; housings, windows and cabin lighting remain authored.

## Startup lighting correction

The user reported an initially blown-out cockpit that later darkened. A same-launch temporal baseline (`startup-temporal-dense`) captures bright surfaces at approximately 9.27 seconds and darker surfaces at 10.27 seconds. The process log places terrain completion at 10.083 seconds. Source tracing found an explicit switch from a 42,000-lux unshadowed provisional sun at an arbitrary direction to the existing mission sun (25,000 lux at the Apollo reference elevation, source-derived direction and shadows). This establishes a concrete initialization discontinuity; it does not establish delayed auto-exposure as a cause.

The fallback now reads lightweight Apollo lighting metadata synchronously and uses the same mission-sun factory as the prepared terrain. Selected-site ephemeris lighting is configured before the first RealityView publication and uses that same factory. Canonical mission intensity, direction, shadow policy and zero-intensity Apollo Earthshine are unchanged. The provisional subtree retains its sun if terrain loading fails; successful publication removes it before attaching the prepared subtree. `--cockpit-startup-timing` records publication/foundation/swap stages with uptime, sun count, intensity, world quaternion and shadow presence for visual correlation.

Fallback and prepared Apollo suns now receive the same altitude-dependent shadow projection. Selected-site installation reapplies any existing vehicle snapshot synchronously to preserve world-space sun direction. Fallback light ownership transfers only after all throwing terrain preparation succeeds. Missing lighting metadata uses an explicit unit identity rotation and the reference exposure.
